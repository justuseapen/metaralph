# MetaRalph Progress Log
Started: 2025-01-12

## Codebase Patterns
- Project uses ESM modules ("type": "module" in package.json)
- TypeScript uses NodeNext module resolution for ESM compatibility
- Run `npm run typecheck` to verify TypeScript before committing
- Use `tsx` to run TypeScript files directly (e.g., `npx tsx src/index.ts`)
- Utilities go in src/utils/ directory
- Database modules go in src/db/ directory
- CLI modules go in src/cli/ directory
- Use `import * as fs from 'node:fs'` for Node.js built-in modules (ESM style)
- Config directory: ~/.config/metaralph/ (use getConfigDir() from config.ts)
- Use initDatabase() from src/db/index.ts to get database instance
- Database uses better-sqlite3 (synchronous API, no async/await needed)
- CLI uses commander for argument parsing (src/cli/index.ts)

---

## Project Context
MetaRalph is an autonomous multi-project orchestration engine built on top of Ralph.

Key architectural decisions:
- TypeScript/Node.js for Ralph ecosystem compatibility
- SQLite for zero-config persistence
- Ink (React for CLI) for terminal UI
- Opt-in project management (user explicitly adds projects)
- Project groups for bundling related repos
- Collaborative PRD creation via conversation threads

Phase 1 focuses on core infrastructure:
- Daemon lifecycle (start/stop/status)
- Database schema
- Configuration management
- CLI framework
- Project and group registry
